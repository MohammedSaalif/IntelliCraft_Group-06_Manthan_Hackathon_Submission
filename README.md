## Overview

Quick-Commerce is an end-to-end machine-learning decision-support prototype designed to analyse historical delivery records and help explore delivery operations.

The project focuses on:

- **ETA prediction:** Estimate delivery time in minutes.
- **Late-delivery risk:** Estimate the likelihood of a delivery exceeding the configured threshold.
- **Demand-zone exploration:** Group geographic order locations to identify areas with different demand patterns.
- **Operational intelligence:** Summarise delivery risk and provide data-informed operational suggestions.
- **Model interpretation:** Compare model performance and inspect influential features.

> **Project status:** Hackathon / decision-support prototype. The system analyses historical records. It does not autonomously dispatch riders, calculate live road routes, or establish that a proposed dark-store location will be profitable.

## Installation

Open the repository folder in VS Code. Select **Terminal → New Terminal** and confirm that the terminal is at the project root.

### 1. Create and activate a virtual environment

```powershell
# Create the environment (skip if .venv already exists)
py -m venv .venv

# Activate it
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, run the following in the current terminal session:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If Jupyter support is not included in `requirements.txt`, install it separately:

```powershell
python -m pip install jupyterlab ipykernel
```

### 3. Register the Jupyter kernel

```powershell
python -m ipykernel install --user --name quick-commerce --display-name "Python (Quick-Commerce)"
```

Make sure VS Code/Jupyter uses this same virtual environment. Installing packages into a different Python environment can cause `ModuleNotFoundError`.

### Optional: baseline package installation

Use this only if `requirements.txt` is unavailable or incomplete:

```powershell
python -m pip install pandas numpy matplotlib seaborn scikit-learn joblib plotly folium streamlit streamlit-folium jupyterlab ipykernel
```

For reproducibility, record the environment after successful installation:

```powershell
python --version
python -m pip freeze > requirements-lock.txt
```

### Pipeline Workflow

The notebook/source workflow is organised around these stages:

1. Dataset loading and initial inspection.
2. Data validation, missing-value checks, and duplicate checks.
3. Data cleaning and feature engineering.
4. Chronological train/validation/test split.
5. ETA regression model training and evaluation.
6. Late-delivery classification and threshold evaluation.
7. Model explainability and permutation importance.
8. Geographic demand-zone clustering and map outputs.
9. Operational risk scoring and summary reports.

Run the complete pipeline in order because later stages depend on outputs generated by earlier stages.

## Assumptions and Limitations

1. **Dataset proxy:** The supplied records describe food delivery, not a complete grocery quick-commerce operation. Restaurant coordinates are treated as service-location/store proxies.
2. **SLA threshold:** A 35-minute threshold is a provisional demonstration setting unless the organisers have confirmed it. It is not an official SLA. If the approved SLA differs, update the notebook, model labels, dashboard, and reports consistently, then rerun the pipeline.
3. **Prediction timing:** Use only features available at the moment the prediction is claimed to occur. Pickup time and delivery outcome are post-event information and must not be used for order-placement prediction. Verify when traffic and weather values become available.
4. **GPS quality:** Invalid coordinates should be flagged and excluded from geographic calculations. This does not require removing the entire order from non-geographic analysis.
5. **Distance:** Haversine distance is straight-line distance, not actual road distance or travel time.
6. **Clustering:** Geographic clusters are exploratory demand groupings. A cluster centre is not a validated delivery boundary, route, or optimal dark-store location.
7. **Courier segmentation:** Rider groups are retrospective descriptive segments. They should not be used for punitive decisions or interpreted without considering route, shift, and demand context.
8. **Model scores:** ETA predictions and late-risk probabilities are estimates, not guarantees. Validate probability calibration before interpreting probabilities as reliable real-world risk percentages.
9. **Causality:** Feature importance and historical correlations do not prove that a factor causes delivery delays.
10. **Business impact:** Cost savings, improved customer satisfaction, and operational gains must be measured in a controlled pilot. Offline model metrics alone do not establish these outcomes.
11. **Live operations:** The prototype does not include complete real-time courier availability, store workload, inventory, dispatch, or road-routing integrations. It is not a production dispatch optimiser.

## Troubleshooting

| Issue | What to check |
|---|---|
| `FileNotFoundError` for `src`, `data`, `models`, or `reports` | Start Jupyter from the repository root or correct `PROJECT_ROOT` to the actual folder. |
| `train.csv` not found | Confirm the filename is `train.csv` and the file is in `data/raw/`. |
| `NameError: raw_df is not defined` | Run the dataset-loading cell before cells that use `raw_df`. If the kernel was reset, restart and run all cells in order. |
| `ModuleNotFoundError` | Activate `.venv`, install `requirements.txt` in that environment, and select the matching Jupyter kernel. |
| Model file not found in Streamlit | Run the notebook through model training and confirm the expected model artifact exists at the path used by the app. |
| Map has missing points or unusual clusters | Check GPS validity, coordinate ranges, clustering settings, and the geographic summary. |
| Results differ from a previous run | Check the dataset version, package versions, random seed, SLA setting, feature list, and notebook execution order. |
